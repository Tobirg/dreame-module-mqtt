# MQTT и Home Assistant — модуль Dreame Local

Модуль для [Dreame Local Agent](https://github.com/Tobirg/dreame_local_agent) 0.10 и новее. Публикует пылесос в MQTT-брокер с автообнаружением Home Assistant и принимает команды из MQTT. Подойдёт брокер, который уже работает для Zigbee2MQTT, или дополнение Mosquitto в Home Assistant.

Модуль не разблокирует робот: он ставится на робот, где агент уже работает.

## Установка и настройка

1. Веб-интерфейс агента → «Модули» → выбрать `mqtt-<версия>.tar.gz` → «Проверить пакет» → «Установить». В проверке пакета видно, что модуль управляет роботом и работает в фоне.
2. В панели «MQTT и Home Assistant» указать адрес брокера, порт, пользователя и пароль, включить «Публиковать робот в MQTT» и нажать «Сохранить и проверить».
3. В Home Assistant с настроенной интеграцией MQTT появится устройство «Dreame r2505» (по модели робота).

Настройки хранятся на роботе в `/data/dreame-local/module-data/mqtt/config.json` (только root) и сохраняются при обновлении модуля. При удалении модуль очищает свои сообщения автообнаружения, и устройство пропадает из Home Assistant.

## Что появляется в Home Assistant

| Сущность | Что делает |
|---|---|
| Пылесос | старт, пауза, стоп, на базу, найти, мощность (`Silent`, `Standard`, `Strong`, `Turbo`), `vacuum.send_command` |
| Батарея | заряд, % |
| Ошибка | название ошибки (`no_error`, `bin_full`, …) |
| Карта | картинка сохранённой карты со станцией, а во время уборки — с роботом, путём, вымытым полом, убираемой зоной и найденными за эту уборку участками, которых нет на сохранённой карте (агент 0.26+); обновляется каждые 15 с, если изменилась |
| Камера карты | та же картинка как камера — для карточки карты; атрибуты `calibration_points` и `rooms` с именами, центрами и контурами комнат (агент 0.22+, контуры — 0.22.2+); текст карточки карты — в панели модуля |
| Настройки | переключатели, списки и числа из раздела «Настройки» панели агента, только те, что есть у робота (агент 0.22+); обновляются раз в 2 минуты и через 3 с после изменения |
| Расходники | остаток ресурса в % для того, что отдаёт модель (щётки, фильтр, датчики, колёса), и кнопки «Reset …» для сброса после замены или чистки |
| Кнопки станции | выгрузка пыли, мойка салфеток, начать и остановить сушку — только если модель робота их поддерживает |
| Ручное управление | кнопки «Move forward», «Move backward», «Turn left», «Turn right» (агент 0.25+): одно нажатие — короткий шаг, около 14 см или поворот. Первое нажатие сводит робота с базы; через ~15 с после последнего нажатия робот сам выходит из ручного режима, вернуть на базу — «На базу» пылесоса |
| Камера и «Camera stream» | только если установлен модуль «Камера» (агент 0.26+). Пока переключатель «Camera stream» включён, камера «Camera» получает 2 кадра в секунду с фронтальной камеры робота; через 10 минут переключатель выключается сам. Кадры не сохраняются на брокере. Атрибуты камеры `state` и `reason` говорят, почему кадров нет (например, робот спит на базе). Включите показ в панели модуля «Камера» |
| «Camera light» | с модулем «Камера» 1.4+: подсветка робота, пока камера снимает (то же, что «Подсветка» в панели камеры) |

Уборка комнат из автоматизации:

```yaml
action: vacuum.send_command
target:
  entity_id: vacuum.dreame_r2505
data:
  command: clean_rooms
  params: {rooms: [1, 2], repeats: 1, suction: 1, water: 2}
```

`command` — любая команда агента (`POST /api/v1/command`), `params` — её параметры.

Зона, точка (робот убирает квадрат 1,5 × 1,5 м вокруг неё) и настройка — координаты в миллиметрах робота, их показывает панель агента:

```yaml
command: clean_zone
params: {zones: [[-5000, 1000, -3800, 2200]], repeats: 1, suction: 1, water: 2}
---
command: clean_spot
params: {points: [[-4400, 1600]], repeats: 1, suction: 1, water: 2}
---
command: set_setting
params: {setting: child_lock, to: true}
```

## Комнаты и пространства Home Assistant

Модуль отдаёт комнаты робота как сегменты пылесоса (`segments` в состоянии, `<база>/clean_segments` для команды). В Home Assistant с поддержкой уборки по пространствам: «Настройки → Устройства и службы → Объекты» → пылесос → шестерёнка → «Сопоставить сегменты с пространствами». Дальше `vacuum.clean_area` с пространствами дома убирает соответствующие комнаты (1 проход, текущая мощность, средняя влажность).

## Карта с выбором зон, точек и комнат

Карточка [xiaomi-vacuum-map-card](https://github.com/PiotrMachowski/lovelace-xiaomi-vacuum-map-card) (ставится через HACS) берёт карту и калибровку у «Камеры карты».

Готовый текст карточки собирает сам модуль: веб-интерфейс агента → «Модули» → «MQTT и Home Assistant» → «Карточка карты для Home Assistant» → «Скопировать». В Home Assistant: панель → «Изменить» → «Добавить карточку» → «Вручную», вставить. В тексте три режима — зона, точка (робот убирает квадрат 1,5 × 1,5 м вокруг неё) и комнаты с именами и контурами с карты робота (модуль 1.6+, агент 0.22.2+). Мощность — текущая у робота (меняется в меню карточки), влажность — средняя, повторы — кнопкой карточки. Если сущности пылесоса или камеры переименованы в Home Assistant, поправьте их в первых строках. После изменения комнат на карте текст нужно взять заново.

Плитки и меню настроек карточка находит сама. В тексте указана платформа `Tasshack/dreame-vacuum`, а модуль называет атрибуты пылесоса так, как их читает её шаблон: `status`, `battery_level`, `cleaned_area`, `cleaning_time`, `cleaning_count`, `total_cleaned_area`, `cleaning_mode`, `mop_wash_level`, `wetness_level`, `tight_mopping`, `cleaning_route`, `cleangenius` (модуль 1.7+, агент 0.24.1+). Плитка появляется для каждого атрибута, который отдаёт робот. Меню «Режим уборки» карточка строит из списка настроек. Текст карточки при этом менять не нужно.

Режимы карточки вызывают `vacuum.send_command` с параметрами-словарём (`command: clean_zone`, `params: {zones: "[[selection]]", ...}`). Платформа карточки **send_command** и кнопка **Generate rooms config** здесь не подходят: они отправляют параметры списком, а MQTT-пылесос Home Assistant списки не передаёт.

## Топики

База по умолчанию — `dreame_local/<id робота>`:

- `<база>/attributes` — атрибуты пылесоса для карточки карты (см. выше), retained;
- `<база>/state` — JSON `{"state", "fan_speed", "battery", "error", "error_name", "station", "status", "consumables"}`, retained;
- `<база>/availability` — `online`/`offline`: робот на связи, агент отвечает, данные свежие. При потере связи с брокером `offline` публикует сам брокер (last will);
- `<база>/command` — `start`, `pause`, `stop`, `return_to_base`, `locate`, `empty`, `wash_mop`, `dry_start`, `dry_stop`, `move_forward`, `move_backward`, `turn_left`, `turn_right`;
- `<база>/fan_speed` — скорость из списка выше;
- `<база>/send_command` — `{"command": "...", "params": {...}}` или параметры на верхнем уровне, как их шлёт Home Assistant; для `clean_zone`, `clean_spot`, `clean_rooms` недостающие `repeats`, `suction`, `water` — 1, текущая мощность, 2;
- `<база>/settings` — JSON настроек (`ON`/`OFF`, подпись варианта или число), retained;
- `<база>/setting/<id>/set` — новое значение настройки в том же виде;
- `<база>/map`, `<база>/map_attributes` — картинка карты и её калибровка с комнатами, retained;
- `<база>/camera_live/set` — `ON`/`OFF`, `<база>/camera_live` — состояние, retained; `<база>/camera` — кадр JPEG в base64, не retained; `<база>/camera_status` — `{"state", "reason"}`, retained;
- `<база>/camera_light/set` — `ON`/`OFF`, `<база>/camera_light` — состояние подсветки, retained.

Автообнаружение: `<префикс>/vacuum|sensor|button|image|camera|switch|select|number/dreame_<id>/.../config`, префикс по умолчанию `homeassistant`.

## Как устроено

Один бинарник `mqtt-bridge` (Go, без внешних зависимостей) служит и обработчиком действий (`status`, `card`, `configure`, `test`, `uninstall`), и фоновым процессом (`mqtt-bridge run`). Агент запускает этот процесс сам, перезапускает при сбое и останавливает при обновлении или удалении модуля. Состояние приходит из потока событий агента `GET /api/v1/events`, команды уходят в `POST /api/v1/command` с токеном модуля.

Ограничения: MQTT 3.1.1, QoS 0, без TLS — рассчитано на брокер в домашней сети.

Нужны Go 1.22+ и GNU tar (Linux, WSL или Git Bash):

```sh
./build.sh                  # dist/mqtt-<версия>.tar.gz и его SHA-256
cd src && go test ./...     # тесты с фейковым брокером и фейковым агентом
```
